# Proximity sound tokens

## Description
First core mechanic toward the party game: position-based audio. Wooden
tokens stand at the four corners of the room, each emitting a distinct
looping sound through an AudioStreamPlayer3D — audible only when the player
approaches, louder/clearer with proximity (inverse-square attenuation), and
panned in 3D so the direction is readable. This is the seed of the
"walk close to eavesdrop" party mechanic.

## Acceptance criteria (when is it done)
- [ ] 4 procedural WAV loops (tick-tock, chime, hum, drip) generated by a
      committed, deterministic script (tools/audio/make_token_sounds.py)
- [ ] SoundToken.tscn entity scene: token mesh + glow light + looping
      AudioStreamPlayer3D with distance attenuation
- [ ] Main scene places one token per room corner, each with its own sound
- [ ] Headless wiring test passes (tokens present, playing, looping)
- [ ] Web build verified: tester walks to each corner and hears each sound
      fade in with distance
